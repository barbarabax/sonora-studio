Melody and chords

YuE2 first writes a plan with the sung melody and the chords, then sings it. You can create it, change the chords and generate the song from that plan. If you don't create one, YuE2 decides on its own.

Add a chord: major, minor, dim, aug, sus…

One chord per bar. You can also write Cdim, Caug, Csus2, G7, Am7… The intro and other parts use the verse loop.

Controls how random the composition is, also between variants. The chosen chords stay in the plan; similarity between melodies is not a guaranteed percentage.

Advanced · plan, MIDI and note editing
Chords and sections

They guide the plan that YuE2 writes on its own (with «Create the plan» or without a plan), so it does not always repeat the same chords. They do not change a plan already made or a cover. They need the new engine (yue2.cpp).

On your PC (yue2.cpp engine) a song takes about as long as it lasts, and the graphics card stays busy meanwhile. The melody and chord plan takes less than a minute.

Choose a part, then tap a note to change it: pitch, rest, split it in two, or merge it with the next. A bar always keeps its length. Change the chords from the boxes above.

For experts: the ABC text of this part
  • % verse starts a part of the song. V: Vocal is the singing voice, V: Ins the instrument.
  • | ends a bar. "D" is the chord of that bar (it can also be changed from the boxes).
  • C D E F G A B are the notes; in lowercase they sound higher. A comma after the letter (D,) lowers it, an apostrophe (d') raises it.
  • ^F is F sharp, _B is B flat, =F is F natural.
  • The number after the note is its length: F4 lasts 4 sixteenths (a quarter note), F2 half of that. A dash (F4-) ties it to the next note.
  • z is a rest (z4 is longer). Z is a whole bar of silence, Z4 four bars.
  • [CEG] are several notes together.
  • In the header: K:D is the key, Q:1/4=88 the tempo, M:4/4 the meter.

Bars and duration calculation

Normal: 4-bar intro and outro, 2-bar breaks between sung sections. Wide: 8 and 4 bars. Spaces already written in the lyrics are counted without adding them twice. You can change each space or reset the added ones.

Denser phrases may need more bars. Written instrumental sections start at 4. Edit the bars to fit your arrangement.

This is a musical estimate: melody, pauses and interpretation can change the timing. BPM refer to the quarter note; in 6/8 a bar contains 3 quarter notes.

This PC · ComfyUI

Sonora can download only the four official ACE-Step model files to this ComfyUI folder. It does not install or change ComfyUI, custom nodes, or settings. Keep at least 22 GB free.

Quick test

Generates a 10-second instrumental clip with the provider selected in the sidebar, to confirm that the whole pipeline runs (files, nodes, GPU memory). It checks that things work, not how the music sounds. The clip is deleted afterwards.

YuE2 · This PC (yue2.cpp)

Sings songs on your own graphics card with the light quantised model (Q8_0). Enter where the engine and the model files are on this computer. The files stay where they are; Sonora only reads them.

Start yue-server --host 127.0.0.1 --port 18087 … on the other computer and open ssh -N -R 18087:127.0.0.1:18087 … to this one. No engine or model files are needed here. The LoRAs the engine loaded at start can be chosen here; add them in its adapters folder there and restart yue-server.
Restart Sonora after saving so the engine is started with these files. The Q8_0 model was tested on a 12 GB graphics card (RTX 2060).

RunPod · Serverless

Your endpoint ID and API key belong to your account. The endpoint and storage charges go directly to RunPod.
Set up RunPod step by step
  1. Deploy a custom RunPod Serverless worker that includes ComfyUI in /comfyui, the ACE-Step 1.5 ComfyUI nodes, Python, and this repository's integrations/runpod/worker.py. A generic endpoint is not enough.
  2. Attach a persistent network volume in the same data center and mount it at /runpod-volume. Provision at least 25 GB and keep about 22 GB free for a fresh setup; the worker reserves an additional 2 GiB.
  3. Start the endpoint and send the test input {"input":{"action":"setup"}} once. The worker downloads the fixed ACE-Step files from the official Hugging Face repository, verifies their SHA-256 checksums, and keeps them on the volume for later runs.
  4. Wait for the setup job to finish successfully and return all four models. The initial download can take a while and uses a running worker; the persistent volume may incur storage charges while retained.
  5. Enter the endpoint ID and API key here, tick the readiness box, choose Verify and save RunPod, then select RunPod as the generation provider.
Review current RunPod compute and storage pricing. Sonora does not create or rent the endpoint or volume for you.

Vast.ai · Existing instance

Sonora connects through SSH to a running instance. It never creates, starts, stops, or destroys Vast resources. Add your PC's SSH public key to Vast, and run ComfyUI on port 8188. Sonora reports missing ACE-Step nodes or models, but you install the missing files on the remote instance yourself.
WELCOME TO YOUR STUDIO

From thought to first play.

  1. Choose the music engine.

    ComfyUI uses the local GPU; RunPod starts a remote GPU and uses credit while it works.

  2. Describe a mood.

    Genre, instruments, rhythm and type of voice. You can use the style suggestions or write freely.

  3. Add lyrics, or not.

    With vocals needs your lyrics. Instrumental generates the music without using the lyrics field.

  4. Check the duration.

    For sung songs it is estimated from the lyrics, BPM and meter; you can correct the bars or choose Manual for a short draft. For instrumentals you choose. Try Light mode; two variants are processed in sequence.

Songs and favorites stay in Sonora's data folder. The archive is reversible. Elaborate mode adds slower musical planning; it does not write lyrics automatically.
